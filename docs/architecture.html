Le Pipeline en 5 Étapes Détaillées
1. Interception Non-bloquante
MiddlewarePacketHandler.java

PowerNukkitX achemine le paquet vers MiddlewarePacketHandler (qui remplace l'original dans PacketHandlerRegistry.MAP). Si aucun middleware ne concerne ce paquet ou cette session, il passe directement à l'original. 

boolean hasGlobal = manager.hasMiddlewares(packetClass);
boolean hasSession = session != null && session.hasMiddlewares(packetClass);

if (!hasGlobal && !hasSession) {
    originalHandler.handle(packet, holder, server); // Passage immédiat sans overhead
    return;
}

MiddlewareContext<T> context = new MiddlewareContext<>(packet, holder, server, originalHandler);
manager.executePipeline(context).whenComplete((_, throwable) -> { ... });
2. Fusion Globale + Session & Tri par Priorités
MiddlewareManager.java

Le gestionnaire fusionne la liste des middlewares globaux et ceux attachés à la NetworkSession du joueur en un temps $O(N + M)$ respectant l'ordre strict des 6 niveaux de priorité : 

LOWEST (0) ➔ LOW (1) ➔ NORMAL (2) ➔ HIGH (3) ➔ HIGHEST (4) ➔ MONITOR (5)

Puis, chaque middleware est validé : état de session (SessionState), filtrage de NetworkHandler, et vérification du mode @Once via switch expression.

3. Chaînage Asynchrone & Contexte Java 25
ScopedValue & CompletableFuture

Chaque middleware est chaîné via chain.thenCompose(...). Le contexte est injecté via ScopedValue de Java 25, permettant à n'importe quel service d'appeler MiddlewareContext.current() : 

chain = chain.thenCompose(_ -> {
    // Injection du contexte Java 25 pour toute la durée de l'exécution
    return ScopedValue.where(MiddlewareContext.CURRENT, context)
            .call(() -> middleware.handle(context))
            .thenRun(() -> {
                // Marque exécuté pour la session si @Once
                if (middleware.getExecutionMode() == MiddlewareExecutionMode.ONCE) {
                    session.markExecuted(middleware);
                }
            });
});
4. Exécution I/O sur Virtual Threads Dédiés
Thread.ofVirtual()

Vos middlewares peuvent effectuer des requêtes bloquantes (SQL, Redis, API HTTP) en les soumettant au virtualExecutor. Le serveur ne subit aucun gel de tick ni de socket : 

return CompletableFuture.runAsync(() -> {
    // Exécuté sur 'middleware-worker-1' (Virtual Thread)
    boolean isBanned = database.checkBan(context.getAddress());
    if (isBanned) {
        context.disconnect("Vous êtes banni !");
        throw new IllegalStateException("Player is banned");
    }
}, MiddlewareManager.getInstance().getVirtualExecutor());
5. Résolution Finale & Retour sur Netty
whenComplete()

Lorsque la chaîne de futures se termine :

  • Si échec ou kick : Le paquet est détruit, la session est fermée si demandé, et le handler original de PowerNukkitX n'est jamais appelé.
  • Si succès : Le paquet est renvoyé sur l'EventLoop Netty pour être traité par le originalHandler officiel de PowerNukkitX.
